# 測試腳本說明

本文件說明 `test/` 目錄下測試腳本的用途與設計思路，主要針對 `auto_day.py` 中的週數計算邏輯進行驗證。

## 背景

根據 `docs/var.md` 的定義，系統需要支援兩種不同的週數計算方式：
1. **##WEEK_SUN##**：以**星期日**作為一週的開始。
2. **##WEEK_MON##**：以**星期一**作為一週的開始。

為了確保計算邏輯正確，我們建立了兩個測試腳本進行不同層次的驗證。

## 測試腳本清單

### 1. `test/test_week.py` (概念驗證 PoC)

*   **目的**：驗證數學邏輯與演算法的正確性。
*   **內容**：
    *   此檔案**獨立運作**，不依賴專案中的其他程式碼。
    *   內部直接實作了 `get_week_sun` 與 `get_week_mon` 兩個函式。
    *   透過硬編碼 (Hard-coded) 的邏輯，確認我們對於「如何計算週數」的理解是否符合 `docs/var.md` 的規格。
*   **使用時機**：在修改主程式前，先用此腳本確認演算法無誤。

### 2. `test/test_week_v2.py` (實作驗證 Integration Test)

*   **目的**：驗證系統實際程式碼 (`auto_day.py`) 的運作是否正確。
*   **內容**：
    *   此檔案會**引用 (Import)** 主程式 `auto_day.py` 中的 `get_custom_week_number` 函式。
    *   它測試的是修改後的通用函式 `get_custom_week_number(date, start_weekday)` 是否能透過參數切換，正確產出上述兩種週數。
*   **使用時機**：在修改主程式後，執行此腳本以確保功能已正確整合至系統中。

## 驗證案例 (基於 2025 年)

根據 `docs/var.md`，我們使用以下日期進行驗證：

### WEEK_SUN (週日為始)
*   **2025-11-15 (六)**：應屬於第 45 週。
*   **2025-11-16 (日)**：應屬於第 46 週 (新的一週開始)。

### WEEK_MON (週一為始)
*   **2025-11-16 (日)**：應屬於第 45 週。
*   **2025-11-17 (一)**：應屬於第 46 週 (新的一週開始)。

## 如何執行測試

在專案根目錄下執行：

```bash
# 執行概念驗證
python test/test_week.py

# 執行實作驗證
python test/test_week_v2.py
```
